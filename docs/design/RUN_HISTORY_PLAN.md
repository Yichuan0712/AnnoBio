# Run / Process 运行历史：计划

状态：实施中。步骤 0 已提交（`1e85d72`）；步骤 1 的签名与存储基础已提交（`75e671f`），迁移、下游联动与 History 界面尚未启用。产品语义见文末"已定"；桌面版存储性能仍需原型验证。基于 `dee3ea4`。接续 [NODE_MODEL_REVIEW.md](NODE_MODEL_REVIEW.md) §6 的"待讨论：History"。

## 目标

1. Run 和 Process 用同一套运行逻辑：跑完变成 "Run completed"，同样的输入不能再跑第二次；这次的结果存进历史。
2. 用户换了 Dataset 或 Prompt（Process 是换 Dataset 或改代码）之后可以再跑；新结果同样存进历史。
3. Run / Process 窗口右上角加 History 按钮，放在"显示面板"按钮左边，用来切换以前的记录。
4. 切换历史时，Pipeline 下游的数据跟着切换；下游没有对应结果的，显示"没有结果"。

## 现状

| | Run | Process |
|---|---|---|
| 跑完后能否再跑 | 不能。按钮变成 "Run completed" | 能，结果直接覆盖 |
| 有结果后能否改输入 | 不能。Prompt、Dataset、映射都锁定 | 能 |
| 结果存在哪 | 节点字段 `runResults`、`runInputContent` | 节点字段 `processDfResults` |
| 历史 | 没有 | 没有 |

另外几点和本计划直接相关：

- **Run 不记录用了什么 Prompt 内容**。Prompt 有 Run 之后仍可以原地编辑，编辑后 Run 的结果和 Prompt 的文字就对不上了。
- **下游 Dataset 是静态副本**。"Save to workspace"（Run）和保存输出分支（Process）都会把当时的结果拷贝成一个新 Dataset，之后上游再变，它不会跟着变（见 NODE_MODEL_REVIEW §3）。
- **Score 实时读 Run 的当前结果**，按规则匹配的分数会跟着 Run 变。但按代码匹配的结果（`scoreMatchResult`）、排除的行和 Review 的结果都存在节点上，不会跟着变。
- **每种节点有两条运行代码**。窗口（`runDetailModal.js`、`processDetailModal.js`）自己调后端，Agent 走画布函数（`startRunNode`、`runProcessNode`）。历史逻辑如果分别写在两处，很容易出现用户和 Agent 行为不一致。

## 核心设计：输入决定当前记录

- 每次开始运行，先分配一条**记录**的 ID，并固定它的输入快照和输入签名。执行期间可以更新状态、进度和部分结果；完成后结果冻结。里面包括：
  - 这次用的全部输入；
  - 结果；
  - 状态（运行中 / 已停止 / 已完成 / 失败）和进度；
  - 时间和模型。
- 每条记录有一个**输入签名**，由下面"什么算输入"里的各项算出来。
- 同一个节点、同一个签名最多有一条新格式记录；启动前完成输入校验后，原子地占用签名并创建记录，再提交后端任务，避免窗口和 Agent 同时启动两次。后端拒绝且确认没有启动任务时释放占用；无法确认时记录为失败，供用户查看/恢复。执行中断后按记录 ID 恢复或处理失败状态，不能另外创建相同签名的记录。
- 节点的**当前记录**就是签名和节点当前输入相同的那条。找不到，节点就显示"没有结果"，Run 按钮可用。

节点上不单独存"当前是哪条"。由此直接得到：

- **同样的输入不能跑第二次**：签名相同，找到的就是已完成的那条，按钮显示 "Run completed"。
- **换输入就能再跑**：签名变了，没有对应记录，按钮可用。
- **在 History 里选一条记录**，等于把节点的输入设回那条记录的输入，当前记录自然就是它。
- **换回原来的输入**，原来的结果自动回来。
- **撤销、Agent 修改、下游跟随**都只需要"输入变了 → 重新找当前记录"这一条规则。

### 什么算输入

| | Run | Process |
|---|---|---|
| 主体 | Input prompt：节点 + 内容（文本、输出格式、输入类型） | 代码 |
| 数据 | Input dataset 的节点 ID 和签名，见下文"Dataset 的签名" | 全部输入 Dataset 的节点 ID 和签名，包括哪个是 `df`、各自的别名 |
| 其他 | 列映射 | — |
| 不算输入，只记录 | 模型（Settings 默认值） | Python 环境 |

**Dataset 的签名**：

- **原始 Dataset**：用内容的规范化哈希；输入签名另外带 Dataset 节点 ID。换到内容相同的另一个 Dataset 节点仍算换输入。
- **派生 Dataset**（来自某个 Run / Process 的结果）：用"Dataset 节点 ID + 来源记录 ID + 分支名"。来源没有当前记录或该分支不存在时，签名不可用，不能把空表当作有效输入。这一条是下游能跟着切换的关键。（已由 [DATA_FLOW_DESIGN.md](DATA_FLOW_DESIGN.md) §3.8 取代：派生 Dataset 已删除，所有 Dataset 按内容签名；读取上游步骤的输入按上游记录签名。）
- 哈希覆盖实际执行会读取的表格内容、列类型、行 ID 和资源引用；统一字段顺序、编码和空值表示。同一份输入在窗口、Agent、保存/重开后要得到相同签名。

### 按钮状态

| 当前记录 | Run 按钮 | 输入选择器 |
|---|---|---|
| 没有 | Run（输入不完整时禁用） | 可改 |
| 运行中 | Stop | 锁定，History 也禁用 |
| 已停止 | Run 显示 Resume；Process 显示 Restart | 可改 |
| 失败 | 查看错误；按该记录的恢复规则重试 | 可改 |
| 已完成 | Run completed（禁用） | 可改 |

和现在相比，Run 有结果之后不再锁定输入，改成"改了输入就是另一条记录"。出错的行仍然算已处理，不重试，和现在一样。

Run 的 Resume 沿用已处理行，从下一行继续写入同一条记录。Process 当前没有逐行检查点；停止后 Restart 会从头执行同一条记录，替换这条记录未冻结的部分输出，按钮不能标成 Resume。失败、取消、关闭窗口、应用重启时的状态要由统一运行入口处理；进程已不在时不能留下永久的"运行中"。完成记录不可重启；已开始执行却失败的记录允许按原输入重试同一条记录，Run 接续已处理行，Process 从头重跑。

## History 按钮与列表

- **位置**：Run 和 Process 窗口标题栏右侧，在显示面板按钮（`attachModalPaneCycle`）的左边。
- **列表**：最新的在上面，当前记录打勾。每条显示：
  - 编号和时间；
  - Run 是 Prompt 名、Dataset 名；Process 是代码的第一行或改动摘要、Dataset 名；
  - 行数和状态（完成 / 停止 / 出错行数）；
  - 模型。
- **选择一条记录**：把这个节点的输入改成那条记录的输入。
  - 如果那条记录用的上游记录不是上游节点的当前记录，上游节点也一起切过去；原始 Dataset 和 Prompt 曾被原地编辑时，也要从记录的输入快照恢复它们当时的内容。
  - 先预演整条祖先链和所有受影响的下游/旁支。若共享的同一个上游节点被要求同时恢复成两种不同内容，拒绝这次切换并说明冲突节点；不能只恢复一半。预览里列出所有会变的节点，例如"同时把 Run A 切到 #2，并恢复 Prompt P 的内容"。
- **运行中**：当前节点或预演会触及的任何节点正在执行时，不允许切换；对应 History 操作不可用或给出明确的运行中提示。

## 下游跟随

> 其中派生 Dataset 写回的部分已由 [DATA_FLOW_DESIGN.md](DATA_FLOW_DESIGN.md) 取代：中间数据不再存在画布上，下游直接读取上游步骤的输出（§3.8）。

某个节点的当前记录变了以后，按拓扑顺序依次处理下游：

| 下游 | 怎么跟 |
|---|---|
| 派生 Dataset | 内容换成上游当前记录的输出。上游没有当前记录、或当前记录没有这个分支时，显示"没有结果"。（只适用于旧项目里还跟随 History 的输出；保存的拷贝不变，见"已定"第 5 条。） |
| Run / Process | 输入签名里含上游记录，所以自动找到对应记录，没有就显示"没有结果"，可以 Run |
| Score | 按规则的分数实时重算（现在就是这样）。代码匹配结果和排除的行按完整 Score 输入分开存 |
| Review | 结果按完整分析输入分开存，没有就显示"没有结果" |

Score / Review 的结果不能只按 Run 记录 ID 归档。Score 的代码匹配结果至少要按 Run 记录、Ground truth Dataset 的节点 ID 与内容签名、匹配代码/规则及相关映射区分；排除行按同一份 Score 输入单独保存。Review 再按完整的 Score 输入与排除行状态、实际使用的 Review 方法/模型等分析输入归档。改 Ground truth、规则或排除行后，不得继续显示旧 Review 为当前结果。

**实现方式**：派生 Dataset 的内容在切换时**写回节点字段**，Score、Review 同理。

切换必须作为一次画布事务处理：先确认需要的历史记录可以读取，再按拓扑顺序写回或清空当前字段，最后只触发一次画布保存。缺少来源/分支时要清空旧的结果字段，并设置明确的"没有结果"状态；执行入口、编译器和导出入口都要拒绝把这种状态当成有效空表。若读取历史失败，保留原来的完整画布状态并报错。

- 现在读 Dataset 内容的地方有一百多处，都读节点字段；有效结果仍从这些字段读取。读取入口还需识别"没有结果"状态，不能把缺失结果当成有效空表。
- 编译器、Pipeline 检测、Export Python Project 继续读节点的当前状态，但必须增加缺失结果检查。
- 其他记录的结果存在历史存储里，用到时再读。

由此带来的约束：

- **保存的输出是拷贝**（2026-10-02 起，见"已定"第 5 条）。下面"派生 Dataset 写回"只适用于旧项目里还跟随 History 的输出。
- **复用整条 Pipeline**：
  1. 把最上游 Run 的 Input dataset 换掉；
  2. 下游全部显示"没有结果"；
  3. 依次再跑一遍。

  以后面板的 Pipeline 运行入口（P1.4）可以一次跑完，每个节点各生成一条记录，签名天然一致。

## 存储

记录不放进画布状态。理由：

- 画布状态每次变化都会全量序列化，撤销也会存快照（NODE_MODEL_REVIEW §1）。
- 历史的全部结果不应随每次画布编辑进入撤销快照；执行中记录只更新对应文件，完成后冻结。

画布状态里只保留当前记录的结果，也就是现在的节点字段。

| | 存在哪 |
|---|---|
| 网页版 | `projects/<id>/history/` 下，每条记录一个文件，外加一个小索引。新增 `/api/projects/{id}/history` 接口；记录文件独立于现有项目 JSON，不能照搬 `agent-conversations` 的整份项目重写方式 |
| 桌面版 | `.yc` 中与画布状态平级的 `history` 字段；现有 `.yc` 是单个 JSON bundle，因此读取和保存仍会处理整个文件，不能声称实现了磁盘层面的按需读取 |

- **读取**：网页打开项目时只取索引，选择记录才取结果；桌面版只能在渲染进程按需传输结果，Electron 读取 `.yc` 时仍会解析整个文件。第 1 步要用代表性的长历史项目测量打开和自动保存耗时；若明显变慢，先改桌面存储格式再发布，不把它留作后续优化。
- **保存**：网页版单条记录和索引分别原子写入，先持久化记录再公开索引，避免崩溃后索引指向不存在的结果；桌面版原子替换整个 bundle。画布里的当前结果是缓存；打开项目时核对签名与历史记录，发现缺失或不一致时不能静默采用缓存。
- **复制、Save As、合并、导出和导入项目**：都带上历史、索引以及记录引用的资源；合并时检查记录 ID 冲突，并修正来源引用。桌面版现有 `projectAssets.save` 会重建 bundle，必须显式保留 `history`；网页版现有复制/合并/导入/导出也要同步处理独立的历史文件。
- **资源清理**：图片/PDF 的可达性除了当前画布，还包括所有保留的历史记录。删除记录或下游级联删除后，才允许清理由它们独占的资源；`getUsedAssetIds` 和网页端对应的清理入口都要使用这份引用集合。

## Agent 同步

按"用户能做的 Agent 都能做，反之亦然"：

- **`inspect_node`**：列出这个节点的历史和当前记录。
- **`run_nodes`**：遵守同一条规则。已完成的输入再跑会被拒绝，错误信息提示换输入或选历史记录。
- **`update`**：可以改有结果的 Run 的 `prompt`、`input_dataset`、`input_mapping`。这会撤掉 `7975427` 里加的锁定，和窗口保持一致。
- **新增 `propose_changes` 操作 `select_history`**：效果同窗口里选一条记录，包括联动上游。
- **删除记录**：如果窗口里能删，Agent 也加对应操作。
- **统一入口**：窗口和 Agent 走同一个运行函数（见下文"实施顺序"第 0 步），历史只在一处写。

## 撤销

- **记录本身不参与撤销**：和现在的运行结果一样。
- **输入的修改照常可撤销**：包括在 History 里选记录。
- **撤销或重做之后**，对所有节点重新找一遍当前记录，再写回节点字段。

注意：`undoHistory.js` 现在会从实时画布合并回运行结果。不重新找一遍的话，会出现"输入回到了旧的、结果还是新的"。

- **已有结果的 Run / Process**：把当前结果做成第 1 条记录，签名按现在的输入计算。

每步单独提交，带测试。第 1、2 步先实现基础设施和联动引擎，不创建或启用新格式记录，保持旧的输入锁定/运行行为；第 3 步启用迁移和新语义，避免中间版本的下游数据错配。迁移时已有重复 Process 运行只保留当前结果为可匹配记录，无法恢复的更早结果不伪造。

## 已定（2026-10-01）

1. **改 Prompt 内容算换输入。** 否则改了 Prompt 之后，Run 仍显示旧结果、又不能再跑，只能新建 Prompt 节点。代价是改一个错字，当前结果也会变成"没有结果"，旧结果在 History 里。（2026-10-02：跑出过结果的 Prompt 已锁定，见第 8 条；这条只适用于还没用过的 Prompt 和锁定前的旧项目。）
2. **改原始 Dataset 的内容算换输入。** 理由同上，结果和数据对得上才有意义。（同上，见第 8 条。）
3. **换 Settings 默认模型不算换输入，只记录。** 否则改一次 Settings，所有 Run 都会变成"没有结果"。代价是同样的输入没法换模型再跑；以后需要时，可以在 Run 窗口加模型选择，让模型成为输入的一部分。
4. **选一条下游记录时，上游一起切。** 这样画布上每个节点显示的都是同一条链上的数据。
5. **保存的输出是拷贝。**（2026-10-02 修订；原为"派生 Dataset 只读"，中间试过"可手改并在 History 里提醒"，均撤回。已由 [DATA_FLOW_DESIGN.md](DATA_FLOW_DESIGN.md) §3.6 取代：保存出来的 Dataset 是普通 Dataset，只用 `savedFrom` 记下来源，不再参与 Pipeline；下面几条只描述当时的做法。）History 记录里存着每次的输出；画布上保存出来的 Dataset 只是拷贝，之后怎么改都不影响记录。
   - Run 的 "Save results" 和 Process 的 "Create dataset"（含 Agent 的 save_run_results / save_process_output）生成的 Dataset 带 `savedCopy`。它保留 `sourceRunNodeId` / `process-to-dataset` 这条产出关系，Pipeline 照常串联、照常重算它；但 History 不再写回它的内容，签名按内容算，没有"没有结果"状态（`datasetHistorySource.js`）。
   - 没被下游用来出结果之前可以改，用过之后按第 8 条锁定。
   - 旧项目里仍跟随 History 的输出（没有 `savedCopy`）照旧工作；第一次修改时变成拷贝。被下游用过的本来就锁定，保持原样，下游已有结果不受影响。
   - 选中一条下游记录：它用的是拷贝，就只恢复拷贝的内容、保留产出关系；它是在输出还跟随 History 时产生的，就把这个输出恢复成跟随状态。
   - 已知差别：Pipeline 重算产出的 Dataset，不会带上画布拷贝里的手改。
6. **每个节点的记录数不设上限。** 可以删除非当前记录（第 4 步）。依赖它的下游记录一起删，删之前确认并列出数量。
7. **出错的行在同一条记录里重试：本计划不做。** 现在出错的行算已处理、不重试，保持不变。
8. **跑出过结果的 Prompt、Dataset 锁定，只能改它的 Duplicate 或新版本。**（2026-10-02）这样每条结果和它用的输入始终对得上，不需要"改过之后"的提醒或手改记录。
   - 锁定条件（`contentLocks.js`）：画布上的 Run 有记录用了这个 Prompt / 输入 Dataset；Process 有记录用了这个输入 Dataset；Score 有记录用它作 Ground truth，或 Score 正在显示结果（上游 Run 有当前结果）、或做过 Review。节点从画布删掉后，它的记录不再锁定任何东西。
   - Process 自己的代码不锁：跑完照样能改，每次运行用的代码由 History 记录（同日先锁后放开）。
   - 锁定只限内容；名字和备注照常可改。Agent 遵守同样的锁定。
   - 规则是"被依赖的不让改、没被依赖的让改"：下游产物（保存的输出拷贝、抽样结果、Score 导出、Review 生成的 Prompt）在被用来出结果之前都可以改。窗口里不显示锁定原因，只是不能编辑。
   - Duplicate 生成的是不连任何东西的独立节点（Process 的副本也不带输入）。
